# AGENTS.md

Guidance for AI coding agents working in Delft-FIAT. Keep this file current when
structure, commands or conventions change.

## What this project is
Delft-FIAT (Fast Impact Assessment Tool) is a lean calculation core that combines
**exposure**, **vulnerability** and **hazard** data to compute flood damages and risk
(EAD, expected annual damage). PyPI name `delft_fiat`, import name `fiat`, CLI `fiat`.

Scope rule: FIAT is the calculation core only. Pre- and post-processing belongs in
[HydroMT-FIAT](https://deltares.github.io/hydromt_fiat/latest) and
[FIAT Toolbox](https://github.com/Deltares/fiat_toolbox), not here.

- Python >= 3.12 (CI/test envs: 3.12, 3.13, 3.14). License: MIT.
- Mixed codebase: Python + Cython (`.pyx`/`.pxd`) + C++17 (FlatGeobuf and GeoTIFF drivers).
  Cython extensions are compiled by [setup.py](setup.py); after editing a `.pyx`, `.pxd`
  or C++ file, reinstall/rebuild before running tests (e.g. `pixi run pip install -e .`).

## Architecture
1. **Settings** (TOML file) are parsed and validated by Pydantic into
   `GeomSettings` or `GridSettings` (`fiat.settings`, via `load_settings`). CLI
   `--set-entry`/`-d` can override entries.
2. **Model** (`fiat.model`) is built from settings. `BaseModel.__init__` reads the
   vulnerability table and hazard grid, then imports the calculation **method** module
   dynamically (`fiat.method.<type>`, e.g. `flood`). It must satisfy
   `fiat.typing.MethodType` (`fn_hazard`, `fn_impact`, column definitions).
   - `GeomModel`: vector exposure (FlatGeobuf) overlaid with hazard, one asset at a time.
   - `GridModel`: raster exposure, same resolution/size/CRS as hazard, per-cell damage.
3. **Execution**: work is chunked (`model/util.py`, `job.py`) and run by worker
   processes started with the `spawn` context, with a log queue back to the parent.
   Because of `spawn`, anything passed to workers must be picklable and entry points
   must be import-safe.
4. **Output**: per-asset/per-cell results plus optional EAD (`method/ead.py`) when
   `risk = true`, written through the drivers.
5. **Checks** (`fiat.check`) validate CRS, extents, duplicate columns and inputs before
   the run; failures raise errors from `fiat.error`.

## Public API
Exported from [src/fiat/\_\_init__.py](src/fiat/__init__.py):
`GeomModel`, `GridModel`, `Settings`, `open_csv`, `open_geom`, `open_grid`, `__version__`.
Also public: `fiat.settings.load_settings`, `GeomSettings`, `GridSettings`, and the `fiat` CLI.

```python
from fiat import GeomModel
from fiat.settings import load_settings

settings = load_settings("settings.toml")
GeomModel(settings).run()
```
(The usage snippet in README.md still shows an older `Configurations` API; do not copy it.)

## Data
- **Settings**: TOML only.
- **Exposure (geom)**: FlatGeobuf (`.fgb`) with a spatial index (hilbert R-tree). Columns:
  `object_type` (optional), `ref` (reference height, needed for flood damage),
  `fn_<type>_<component>` (vulnerability curve name) with matching
  `max_<type>_<component>` (maximum value). Multiple files allowed.
- **Exposure (grid)**: GeoTIFF or NetCDF (GDAL-compliant), same grid as hazard.
- **Hazard**: GeoTIFF / NetCDF flood depth or elevation maps. Event map, or several maps with
  return periods (`rp`) for risk. Assets must not fall outside the hazard extent.
- **Vulnerability**: CSV, first column water depth, other columns damage fractions (0-1) per
  curve name. Header rows `#UNIT=<unit>` and `#METHOD` (e.g. `mean`, `max`) per curve.
- Units (depth, reference height) must be consistent across hazard, exposure, vulnerability.
- CRS is checked and non-matching inputs are reprojected to the model CRS.
- Core libs: numpy, scipy, netcdf4, pyproj, pydantic, regex. No pandas/GDAL at runtime
  (pandas only for docs).
- User docs: [docs/user_guide/](docs/user_guide) (`data/`, `settings/`).

## Environment and commands
Use **pixi** (see `[tool.pixi.*]` in [pyproject.toml](pyproject.toml)); do not use pip/conda/venv
directly for the project environment.

`pixi run -e test-py312 test`).

## Code conventions
- **Ruff** (line length 88; rules E, F, I, PT, D). Docstrings follow **numpy** convention and
  are required on public modules/classes/functions in `src/` (not in `test/`).
  `ruff format` is the formatter. Fix lint before committing.
- Cython: double-quoted strings (`double-quote-cython-strings`), `cython-lint`; C++ formatted
  with `clang-format` 19 (generated FlatGeobuf files are excluded).
- Type hints in new code (`mypy` with pydantic plugin; `disallow_any_generics`). Use modern
  syntax (`X | None`, `list[str]`).
- Names for config keys and recurring strings are constants in `fiat/util.py`
  (e.g. `EXPOSURE`, `HAZARD`, `FIAT_METHOD`). Reuse them instead of repeating literals.
- Logging: `logger = spawn_logger(__name__)` from `fiat.log`; never use `print` in library code.
- Raise errors from `fiat.error` for user-facing failures; validate inputs via `fiat.check`.
- Model properties that change state go through `settings.update(...)` (see `BaseModel`).
- Module layout: package `__init__.py` files re-export; `from .x import *` is allowed there.
- Keep the core lean; do not add pre/post-processing features (see Scope above).

## Testing conventions
- `test/` mirrors `src/fiat/` (e.g. `test/driver/test_driver_csv.py`). Shared fixtures are in
  `test/conftest.py` and per-folder `conftest.py`.
- Markers: `integration`, `system`, `serial`. Default CI coverage run excludes integration/system.
- Every new feature or bug fix needs a pytest test. Use `tmp_path` and the `*_tmp_path`
  fixtures to avoid mutating files in `data/`.
- Integration tests in [test/integration/test_run.py](test/integration/test_run.py) run whole
  models from the `data/*.toml` settings (`geom_event`, `geom_risk`, `grid_event`, ...).

## Contributing workflow
1. Open or find an issue first; fork; branch from `main`.
2. Descriptive commit messages; format/lint with Ruff (pre-commit hooks: `pixi run install`).
3. Add tests; update docs under `docs/` if behavior or settings change.
4. Add an entry under **Unreleased** in [docs/changelog.qmd](docs/changelog.qmd)
   (sections: Added, Changed, Deprecated, Fixed, Removed).
5. Open a PR to `main` using [.github/pull_request_template.md](.github/pull_request_template.md)
   (issue addressed, explanation, checklist: tests, up to date with `main`, hooks pass, docs).

## Gotchas
- Cython/C++ changes require a rebuild; stale compiled extensions cause confusing failures.
- Windows and Linux are both supported (`linux-64`, `win-64`); avoid OS-specific paths/shell.
- Multiprocessing uses `spawn`; guard entry points and keep worker args picklable.
- Do not commit generated artifacts: `bin/`, `build/`, `dist/`, `docs/_site`, `docs/_freeze`,
  `docs/_inv`, `.cov`, files generated into `data/`.
- `docs/` is excluded from ruff; notebooks should have outputs cleared
  (`docs/examples/clear_notebooks.py`).
